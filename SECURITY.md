# Security Policy

## Supported versions

No release exists yet; report against `main`. After the first release, fixes land on the latest release.

| Version | Supported |
| :--- | :--- |
| 0.1.x (MVP) | Yes |

## Reporting a vulnerability

Please **do not** open a public issue.

Use [GitHub's private vulnerability reporting](https://github.com/LebedevKondakovSergeyVach/grove/security/advisories/new).

Please include the version (`grove --version`), your OS and shell, what an attacker gains, and the steps to reproduce. You can expect an acknowledgement within a week, and credit in the release notes unless you would rather stay anonymous.

## What is in scope

Grove runs `git` in several repositories, reads a workspace file and user settings, and prints shell code that the user's shell evaluates. The interesting boundaries are:

- **Shell injection.** Output of `grove init` is passed to the shell's `eval`. Every interpolated value must go through the single `shell_quote` function. A way past it is a vulnerability.
- **Workspace file handling.** Reading a hostile workspace file or settings file must not lead to code execution.
- **Git invocation.** Repository paths, remotes and branch names from the workspace file must not be interpreted as options or shell syntax.

Workspace commands are not implemented in 0.1.0. These boundaries apply as they are added.

## What is not in scope

- The git remotes you configure. Grove runs `git` against them; it does not vet them.
- Running Grove with a workspace file or settings file that another local user can write. Their contents are trusted as far as any file in your home directory.
- Reports generated by an automated scanner with no demonstrated impact.
